# Direct play on a full queue

## Context

The server currently rejects a direct song or radio selection when the
authoritative queue is full and the request does not replace an already active
entry. Direct playback is an explicit force-load action, so it must make room
by removing the first queue entry instead of showing `The queue is full.`.

## Goal

When a client directly starts a song or selects a radio station while the
server queue is full:

- remove the entry at queue position 0;
- place the requested song or radio station at the front;
- keep the queue at its configured maximum size;
- begin the requested playback normally.

Normal queue additions remain capacity-limited and continue to report a full
queue.

## Design

Keep the behavior in `PlaylistState`, where queue capacity and front-of-queue
mutations already live:

- `prepareImmediatePlayback(...)` evicts index 0 only when a new song is being
  directly selected and no current entry is already removed as part of the
  replacement.
- `selectRadioAtFront(...)` evicts index 0 only when a new radio station must
  be inserted into a full queue whose front is not already a radio station.
- Existing-current replacement and front-radio replacement remain atomic and
  do not evict an additional entry.

`PlaylistManager` continues to validate requests and starts playback, but does
not change the capacity behavior of ordinary add or bulk-add handlers.

## State and compatibility

The queue remains server-authoritative. No client, packet, or protocol changes
are required. Queue revisions and existing playback transitions continue to be
generated by the existing state mutation and manager broadcast paths.

## Verification

Add regression tests for:

1. a full queue with no active track where direct song playback evicts the old
   first entry and keeps the configured size;
2. a full queue where direct radio selection evicts the old first entry and
   keeps the configured size;
3. normal add behavior still rejecting a full queue.

Run the focused state/manager tests and the complete Gradle test/build checks.

## Non-goals

- changing the configured queue maximum;
- changing ordinary song, chart, playlist, or radio queue additions;
- changing client-side direct-play controls or network packet formats.
